# 全艇チューニングダッシュボード 設計書 (roadmap #22)

- **日付**: 2026-08-24
- **ステータス**: 設計確定 → 実装プランへ
- **スコープ**: 推移グラフ ＋ 470船図を囲む配置 ＋ 時系列(期間)バー
- **非スコープ(据え置き)**: チューニング適合点数、各艇の真後ろ画像の登録/並べ比較(roadmap #22 の残りは別イテレーション)

---

## 1. 目的

反省で入力した**艇セッティング(rig)値を艇横断・時系列で見比べる**ダッシュボードを作る。
中央に470の設計図を置き、各パラメータの推移ミニグラフを「そのデータが指し示す船体位置」の
周囲に配置。下部の期間バーで時系列(表示するx域)を変更できる。

## 2. データ源とx軸

- チューニング値は各練習ファイル `*.sailviz.json` の `reflections[].rig` に入っている
  (キーは `src/reflections.js` の `RIG_FIELDS` = `boatNo` ＋11パラメータ)。
- ダッシュボードは**保存フォルダ(`projectDir`)の全 `*.sailviz.json` を読み込み**、
  全反省の `rig` を集めて**船番号(`boatNo`)でグルーピング**する。
- **対象6艇**: `4899, 4859, 4807, 4677, 4519, 4304`。この6艇以外の `boatNo` は除外。
- **x軸の時刻(ms)**: `reflection.practice?.startMs`
  → 無ければ練習ファイルの最古実データ時刻(`summary.js` の `earliestContentMs` 相当)
  → それも無ければ `reflection.createdAt`。
- **既知の制約**: 反省は練習ファイルに埋め込まれているため、集計に全ファイル(大きな `points` 込み)を
  読む必要がある。MVPは素直に全読み。将来は反省だけのインデックス化を検討。

## 3. 画面・ルーティング

- 現状の body クラス切替(`view-home` ⇄ トラック画面)に **`view-dashboard`** を追加し、
  `index.html` に **`#dashboard-screen`** セクションを新設(home と同じく全面表示)。
- **ホームの `SailViz` タイトル横**(`#home-bar`)に
  **「🔧 チューニングダッシュボード」リンク**を追加 → `showDashboard()`。
- ダッシュボード側にヘッダ(タイトル＋**「← ホーム」リンク**)。`showHome()`/`showDashboard()` は
  既存の `showHome()` と同じく body クラスの付け替えのみ(トラック画面の canvas 再フィットには触れない)。

## 4. レイアウト(470を囲む配置)

```
 ┌───────────── #dashboard-screen ─────────────┐
 │  [← ホーム]  チューニングダッシュボード        │
 │                                              │
 │   ┌chart┐        ┌470画像┐        ┌chart┐   │

 │   ┌chart┐        │  船   │        ┌chart┐   │
 │      … (rig 11パラメータのミニグラフを周囲に) … │
 │                                              │
 │  [=====期間ブラシ(日付レンジ)===============] │
 └──────────────────────────────────────────────┘
```

- 中央: `sample-data/470.jpg`(416×554, 横向き側面図)を `<img>` で表示。読込失敗時はプレースホルダ枠。
- 周囲: **rig 11パラメータ(`boatNo` を除く)ごとのミニ折れ線グラフ**を絶対配置。
  各グラフから、対応する船体アンカー点へ**リーダー線(SVG)**を引く。
- 各ミニグラフ: そのパラメータの**推移**を、**対象6艇＝最大6本の色線**で描く。
  タイトル(日本語ラベル=`RIG_LABELS`)＋y範囲(min/max)を薄く表示。
- **色割り当て**: 6艇に固定パレット(実装側で適当に決めてよい/コントラスト重視)。
  凡例(艇番号→色)をダッシュボード上部に1つ表示。

### パラメータ→船体アンカーの対応(初期値・調整可)

`boatlayout.js` に正規化座標 `{x,y}`(画像左上=0,0 / 右下=1,1)と配置象限で定義する。
470側面図(マスト中央右・メインセイル中央左・ジブ前方左・ブーム下辺・ハル/センターボード/ラダー下部)に基づく初期値:

| パラメータ | 意味 | アンカー(概略) |
|---|---|---|
| rake | マストレーキ | マスト上部 (0.66, 0.10) |
| prebend | プリベンド | マスト中央の曲がり (0.64, 0.38) |
| foreTension | フォアステイ張力 | フォアステイ (0.40, 0.28) |
| sideTension | シュラウド張力 | シュラウド/チェーンプレート (0.58, 0.55) |
| bridleHeight | トラピーズブライダル高 | ハウンズ付近 (0.66, 0.22) |
| gear | ギア | メインセイル中程 (0.46, 0.30) |
| vangPull | バング引き量 | ブーム根元/バング (0.60, 0.72) |
| jibLeader | ジブリーダー | ジブクリュー下 (0.44, 0.58) |
| jibPull | ジブ引き量 | ジブ後縁 (0.40, 0.50) |
| puller | プラー | ブーム/デッキ (0.52, 0.78) |
| peakRope | ピークロープ | ブーム端付近 (0.48, 0.70) |

(座標は実装時に画像を見て微調整。ユーザが後から触れるよう定数表に集約する。)

## 5. 下バー(時系列変更)

- ダッシュボード下部に**期間ブラシ**(2ハンドルの日付レンジ)を1本置く。
- ドラッグで `[from, to]`(ms)を絞ると、全ミニグラフが**そのx域だけ**で再描画。
- 全体ドメインは集計結果の `min/max` 時刻。目盛りに日付ラベルを数個表示。
- 既存 `timeline.js` の思想を流用した軽量版(canvas 1枚 or SVG)。cropハンドルの当たり判定・
  域クランプなどの純ロジックは小さなヘルパに切り出しテストする。

## 6. モジュール分割

| ファイル | 役割 | 依存 | テスト |
|---|---|---|---|
| `src/tuning.js` | 全練習(deserialize済 project 配列)→ `{boats, series[param][boat]=[{tMs,value}], domain}` に集計。x時刻フォールバック、6艇ホワイトリスト、tMs昇順ソート、null値スキップ。 | なし(純) | ○ 単体 |
| `src/linechart.js` | 多系列折れ線を**SVG文字列**で生成。値→座標変換、null飛ばし、x域(`from,to`)フィルタ、y自動スケール。 | なし(純) | ○ 単体 |
| `src/boatlayout.js` | rigパラメータ→船体アンカー(0..1)＋配置象限の定数表と参照ヘルパ。**boatNo以外の全RIG_FIELDSを網羅**。 | `reflections.js`(RIG_FIELDS) | ○ 網羅 |
| `src/dashboard.js` | 上記を束ねてDOM描画・期間ブラシ配線・`projectDir` から全ファイル読込。 | 上記＋projectfs/summary | 手動 |

- `app.js` は最小限の配線のみ追加: リンク要素・`showDashboard()`・body クラス切替。
  重いロジックは持ち込まない(app.js は既に大きいため)。

## 7. スタイル(styles.css)

- `#dashboard-screen`(全面・home と同様の表示切替), 中央画像枠, `.tuning-chart`(絶対配置),
  リーダー線(SVG overlay), 凡例, 期間バーを追加。既存のトーンに合わせる。

## 8. テスト方針(TDD)

純モジュールを先にテスト:
- `tuning.collectTuning`: 複数練習の集計 / x時刻の3段フォールバック / 6艇ホワイトリスト /
  同一艇の昇順ソート / rig値が null の欄はスキップ / 対象外 boatNo の除外。
- `linechart`: 値→座標(y反転/範囲), null区間の分断, x域フィルタ, 単一点/空系列の非破綻。
- `boatlayout`: `RIG_FIELDS` から `boatNo` を除く全キーにアンカーが定義されている(網羅)。
- 期間ブラシの純ヘルパ(域クランプ, x↔時刻変換)。
- DOM描画・画像配置・ドラッグは手動確認。

## 9. 段階(実装プランで詳細化)

1. `tuning.js` (集計) + テスト
2. `linechart.js` (SVG折れ線) + テスト
3. `boatlayout.js` (アンカー表) + テスト
4. `index.html`/`styles.css`: `#dashboard-screen` 枠・ホームのリンク
5. `dashboard.js`: 画像＋グラフ配置＋リーダー線 描画(静的域)
6. 期間ブラシ + 全グラフ再描画の配線 + 純ヘルパのテスト
7. `app.js` 配線(`showDashboard`/リンク)・手動確認

## 追記 (2026-08-25): グラフ強化

初版リリース後、UI強化を実施。当初「外部依存なし・自作SVG折れ線」だったが、
見栄え/対話性の要望により **Chart.js を採用**（下記の依存例外を明記）。

### 追加した内容
1. **グラフの軸＋数値ラベル**: 各ミニグラフにY最大/最小・X端の日付ラベルを表示。
   （`linechart.js` に `axis` オプションを後方互換で追加。※ Chart.js 移行後は dashboard から不使用だが、
   モジュールとテストは軽量フォールバックとして残置。）
2. **数値まとめ表**: グラフ下に「行=練習日×艇 / 列=11パラメータ」の表。期間バーに連動。
   `tuning.js` に `collectTuningRows`、新規 `tuningtable.js`（純関数・HTML生成）。
3. **Chart.js でリッチ図示**: ミニグラフを Chart.js の line チャートに置換し、
   **クリックで拡大**（凡例＋ツールチップ付きの対話グラフをオーバレイ表示）。
   新規 `chartview.js`（Chart.js を隔離、純関数 `buildChartDatasets` はテスト、描画は手動確認）。
   期間バーのドラッグは各チャートの x範囲を `update('none')` で更新して連動（再生成せず軽量）。

### 依存の例外（no-build 制約の更新）
- **Chart.js 4.4.6 (auto build)** を `vendor/chart.esm.js` に **自己完結ESMとして同梱**（203KB、外部import無し）。
  ビルドツールは引き続き不要、CDN不要＝**オフラインでも動作**。
- x軸は linear(tMs)＋ticksをMM-DD整形として、**日付アダプタ等の追加依存は入れない**（単一依存に限定）。
- 更新方法: `https://esm.sh/chart.js@4.4.6/es2020/auto.bundle.mjs` を再取得して差し替え。

### スコープ据え置き（変更なし）
適合点数・真後ろ画像比較は引き続き別イテレーション。
