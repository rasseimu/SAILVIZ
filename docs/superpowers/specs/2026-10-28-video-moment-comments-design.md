# 練習動画への瞬間コメント(②)設計

①(練習動画の自動紐付け、`2026-10-28-practice-video-auto-link-design.md`)の続き。③ プロ動画の勉強ページは別の設計で扱うが、本設計のサーバー保存・表示部品を流用する。

## 目的と理由

動画そのものにはコメントを付けられず、「12:34 のタックで体重移動が遅い」のような指摘を残して共有する手段がない。チーム(コーチを含む)で同じ動画の特定の瞬間にコメントを付け合い、全員が読めるようにする。

成功の姿: 誰かが練習動画の特定の瞬間に付けたコメントが、他のメンバーが同じ練習を開いて同じ動画を再生したときに、その瞬間に表示される。コメント一覧から選ぶとその瞬間(動画と GPS の両方)に飛べる。

## 目標

1. 練習動画の再生中、「今の位置にコメント」で現在の再生位置(動画内 ms)にコメントを付けられる。
2. 再生中、コメントの位置に来たら動画の上(または直下)に表示する。表示は位置から約4秒間。
3. 開いている動画のコメント一覧を時刻順に表示し、選ぶとその位置へ動画をシークする(既存の `seeked` → `syncFromVideo` で GPS の再生位置も追従する)。
4. コメントはサーバー(DB)に保存し、練習を見られるメンバー全員が読める。
5. 書いた人の名前と書いた日時を表示する。

## 非目標

- 地図の軌跡上にコメントのピンを出すこと(将来の候補)。
- 返信・スレッド・メンション・通知。
- ファイル版ストア(`STORAGE=file`)でのコメント。ファイル版ではコメント API は 503 を返し、画面はコメント欄を出さない(既存の反省コメント API と同じ扱い)。
- 動画ファイルのサーバー保存。

## アンチゴール

- 他人のコメントを本人以外(管理者を除く)が消せる/書き換えられる。
- 見る権限のない練習のコメントが読める。
- 動画を削除・再追加したらコメントが消える(コメントは動画の一覧と独立に保存する)。
- 旧データ(練習データの `videos`)の形を変える。

## 権限(利用者決定 2026-10-28)

- 読む: その練習(compat の `GET /api/projects/:id` で読める練習)を読める人。
- 書く: ログインしたアカウント(policy の `user` 主体)で、その練習の組織のメンバー。共有ログイン(`legacy` 主体)は個人を特定できないため書けない(読めはする)。※私の判断。
- 編集: 書いた本人だけ。
- 削除: 書いた本人、またはその組織の管理者(`org_admins`)。

## データ

- 動画の指し方: 練習ID + 動画の `name` + `t`(①と同じ組。`t` は整数 ms)。
- 新しい表(migration `009_video_comments.sql`)。③でも使うため共通の表にする。
  - `id` TEXT PK(ランダム)
  - `org_id` TEXT NOT NULL
  - `scope` TEXT NOT NULL — `'practice'` | `'study'`
  - `practice_day_id` TEXT NULL — `scope='practice'` のとき練習ID
  - `video_key` TEXT NOT NULL — 練習: `name` と `t`、勉強: `name` と `size`(③)。区切りや形は builder が決めてよいが、名前に何が含まれても衝突しないこと(例: JSON 配列文字列)。
  - `video_name` TEXT NOT NULL(表示・診断用)
  - `position_ms` INTEGER NOT NULL(0 以上)
  - `text` TEXT NOT NULL(1〜1000字)
  - `author_user_id` TEXT NOT NULL
  - `created_at` / `updated_at` INTEGER
  - 索引: `(practice_day_id, video_key)`、`(org_id, scope, video_key)`
- 練習を削除したとき: コメントは消さずに残してよい(練習の削除は一時保管から復元されうるため)。※私の判断。

## API(案。ルート配置は builder 判断)

- `GET /api/projects/:id/video-comments` → その練習の全動画のコメント `[{ id, videoName, videoT, positionMs, text, authorUserId, authorName, createdAt, updatedAt, canEdit, canDelete }]`(位置順)。
- `POST /api/projects/:id/video-comments` 本文 `{ videoName, videoT, positionMs, text }` → 作ったコメント(201)。
- `PATCH /api/video-comments/:cid` 本文 `{ text }` → 更新後(本人のみ)。
- `DELETE /api/video-comments/:cid` → `{ ok: true }`(本人か組織管理者)。
- `authorName` は既存の反省コメントと同じ決め方(組織の旧氏名 → 表示名)。
- エラーは既存のアプリ向け API と同じ `{ error: { code, message } }`。読めない練習・存在しないコメントは 404、未ログインは 401、権限なしは 403、入力不正は 422、ファイル版は 503。
- `canEdit` / `canDelete` はサーバーが主体から計算して返す(画面はそれでボタンを出し分ける)。

## 画面

- 既存の動画パネル(`#video-panel`)の動画の下にコメント欄を足す。
  - 「今の位置にコメント」ボタン → 入力欄(現在位置 `m:ss` を表示)→ 送信。押した瞬間に動画を一時停止する。
  - 一覧: `m:ss 名前 本文`、時刻順。クリックでシーク。本人には編集・削除、管理者には削除を出す。
  - 再生中、現在位置が `positionMs`〜`+4000ms` のコメントを動画の上に重ねて表示する。
- 練習を開いたとき(`loadPractice` 後)にその練習のコメントをまとめて取得し、動画パネルを開くたびに該当動画の分を出す。動画パネルを開いた時と、コメントを書いた・消した時に取り直す。
- 未保存の練習(サーバーに練習 ID が無い)では、コメント欄に「練習を保存するとコメントできます」と出す。
- 書けない主体(未ログイン・共有ログイン)には入力ボタンを出さず、一覧だけ出す。
- モバイル幅(390px)でも欄が崩れないこと。

## 制約

- バニラ ESM・ビルドなし、サーバー依存ゼロ、`node:sqlite`。
- 新ロジック(権限判定、入力検証、キーの組み立て、表示中コメントの選択)に単体テスト。テストデータに実名を入れない。
- 既存の動画パネル・GPS 同期の動きを変えない。

## builder に任せること

- ルートファイルの分け方、repo の置き場所(`appRepo` 拡張か新 repo か)。
- オーバーレイ表示の見た目、一覧の最大高さとスクロール。
- 取得のキャッシュ・再取得のタイミングの細部。
