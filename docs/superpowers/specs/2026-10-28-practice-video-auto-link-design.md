# 練習動画の自動紐付け(①)設計

作業 ①〜③ のうち ①。② 練習動画への瞬間コメント、③ プロ動画の勉強ページは別の設計で扱う。

## 目的と理由

今は練習を開くたびに Finder で `練習動画/2026練習/8 27(木)` のような日付フォルダを探し、「同期フォルダから取込」で選ぶ必要があり、手間がかかる。
動画は Google Drive for Desktop の同期フォルダにあるが、大学 Workspace アカウントの制約で Drive API / OAuth は使わない(既存方針)。同期フォルダをローカルファイルとして File System Access API で読む方式を続ける。

成功の姿: 最初に1回 `練習動画` フォルダを選べば、以後は練習を開くだけでその日の動画が練習に紐付き、チーム全員の一覧に載り、各自の PC では自分の同期フォルダからつながる。

## 目標

1. 動画ルート(`練習動画` フォルダ)を1回選んで IndexedDB に記憶する。
2. 練習を開いたとき(GPS 軌跡がある場合)に自動で:
   - 練習日(日本時間)の年・月・日を求める。
   - `<ルート>/<年>練習/` の中から月日が一致するフォルダを探す。
   - そのフォルダ直下の動画のうち、埋め込み撮影時刻が GPS 範囲と重なるものを取り込む(既存 `scanFolderVideos` の判定をそのまま使う)。
   - 練習データにすでにあるが自分の PC で未リンクの動画を、見つかったフォルダ内の同名ファイルで再リンクする。
3. 新しく取り込んだ動画は、その場でサーバーの練習データに追記保存し、チーム全員に見えるようにする。
4. 結果と失敗理由を表示する(「3本取込」「8/27 のフォルダが見つかりません」「動画フォルダ未設定」など)。

## 非目標

- Google Drive API / OAuth / Picker の利用。
- 動画ファイルのサーバー保存(動画は今後もサーバーに置かない)。
- 自動で動画を練習データから削除すること(削除は手動のみ)。
- 手動で消した動画を次回以降も出さないための除外リスト(利用者決定で不要)。
- `プロ動画` など `◯◯練習` 以外のフォルダの扱い(③で扱う)。
- 動画へのコメント(②で扱う)。

## アンチゴール(動いても失敗とみなすもの)

- 自動取込の保存で、他のメンバーが同時に編集した反省・イベント等を上書きして消す。
- 許可ダイアログやフォルダ選択ダイアログが、練習を開いただけで勝手に出る。
- 別の日・別の練習の動画が紛れ込む。
- 旧形式の練習データ(`videos` の形)が読めなくなる。

## フォルダ名の解釈(決定事項)

実際のフォルダ名の例: `1 12（月）`、`1 28(水)`、`2 21`、`2 22日`、`8:27`、`7 5(日)ファミリーデイ`、`9 11(金)（駿水さんコーチング2日目）`、`10 17(土）`。

- 年はフォルダ名に無く、親フォルダ `<年>練習`(例 `2026練習`)から決まる。
- 月日フォルダは、名前の先頭から「月」と「日」の2つの数字を読み、それ以外(括弧の全角/半角、曜日、`日`、メモ)は無視する。区切りは空白・`:`・`/` を許容する。
- 同じ月日に一致するフォルダが複数ある場合(例 `8 27(木)` と `8:27`)は全部を走査する。
- 走査するのは月日フォルダの直下のみ(サブフォルダは見ない)。※builder 判断で変えてよい。
- 最終的な取込可否は撮影時刻と GPS 範囲の重なりで決めるので、フォルダ解釈が甘くても他の練習の動画は入らない。

## 動作の流れ

### ルートの設定
- 既存の「同期フォルダから取込」付近に「動画フォルダを設定」操作を追加し、`showDirectoryPicker`(読み取り)で選ばせる。
- ハンドルは既存 `src/dirhandle.js` と同じ IndexedDB ストアに、別キー(例 `videoRootDir`)で保存する。既存の `projectDir` キーには触らない。
- 選ばれたフォルダが `練習動画` ではなく `2026練習` 自体だった場合も動くようにする(ルート直下の名前が `\d{4}練習` のフォルダか、ルート名自体がそれかで判定)。※私の判断。

### 練習を開いたとき
- トリガーは練習の読込完了時(`loadPractice` の成功後)と、GPS CSV を新規に読み込んだ直後。
- ハンドルの権限を `queryPermission` で確認し、`granted` のときだけ自動で走査する。`requestPermission` はユーザー操作が必要なため、自動では呼ばない。
- 権限が `prompt` のときは、ボタン表示を「動画フォルダを許可」に変え、押されたら `requestPermission` → 走査する。
- 練習日は `state.practiceDate` があればそれを、無ければ GPS の最初の時刻を使い、日本時間(Asia/Tokyo)で年月日を出す。日付をまたぐ練習は考えない(開始日のみ)。※私の判断。

### 取込と保存
- 取込後の画面上の扱い(`placeVideo`、再リンク、`loadVideoDuration`)は既存の `importFromVideoFolder` と同じ。
- 新しく追加した動画(ファイル名が練習データに無かったもの)があれば、サーバーへ**動画だけを追記する専用 API** を呼ぶ。練習全体の PUT(`store.writeProject`)は使わない。
  - 案: `POST /api/projects/:id/videos`、本文 `{ videos: [{ id, t, name, durationMs }] }`。
  - サーバーは現在の練習データの `videos` を読み、`name`+`t` が未登録のものだけを足して保存する(既存の項目は変更しない)。同時に複数人が開いても重複しない。DB 版は1トランザクションで読んで書く。
  - 権限は既存の練習 PUT と同じ(`gateWrite` + `canPutDay`)。書けない人(閲覧のみ)は呼ばず、自分の画面にだけ出す。書けない場合はステータスに「閲覧のみのため練習データには保存していません」と出す。
  - 応答に保存後の `videos` を返し、画面側の一覧と揃える。※私の判断。
- 練習がまだサーバーに無い(新規 GPS を読み込んだだけで未保存)場合は、追記 API を呼ばずに画面上だけ取り込む。ユーザーが「保存」を押したときに既存の全体保存で一緒に保存される。
- 追記保存した後、画面の「未保存」状態は変えない(動画以外の未保存の編集を誤って保存済み扱いにしない)。

### 動画の見分け方(決定)
- 練習内の動画は **`name` + `t`(録画開始の絶対ms)** の組で同一とみなす。iPhone の `IMG_0001.MOV` のように別人の動画と名前が重なりうるため。
- 追記 API の重複判定もこの組で行う。
- 再リンク(未リンク動画をローカルファイルにつなぐ)は名前で候補を集め、候補が複数ある場合は埋め込み撮影時刻が `t` に最も近い(±2秒以内)ものを選ぶ。候補が1つならそのまま使う(旧来どおり)。
- `id`(`vid0` 等のローカル連番)は今回は変えない。②のコメントも `name` + `t` で動画を指す。

### 手動削除(利用者決定 2026-10-28)
- 手動で一覧から消した動画が、次に練習を開いたとき自動取込で戻ってくるのは**許容**する(本当に不要なら利用者が Drive から消す)。除外リストは持たない。

### 全体保存で他人の追記を消さない(決定)
- 画面は、練習を開いた時点の動画・自分で追加した動画・自分で消した動画のキー(`name`+`t`)を「既知」として覚えておく。
- 「保存」(全体 PUT)の直前に、サーバーの最新の動画一覧を軽い API(`GET /api/projects/:id/videos`)で取り、**既知でない動画**(自分が開いた後に他のメンバーが追記したもの)を画面の一覧へ足してから PUT する。自分で消した動画は既知なので戻さない。
- 取得に失敗したら、今までどおりそのまま保存する(保存自体を止めない)。

### 表示
- 既存のフォルダ取込ボタンの状態表示(`setFolderBtn`)とステータス行を使う。
- 主なメッセージ: 「動画フォルダ未設定」「動画フォルダを許可」「2026練習 フォルダが見つかりません」「8/27 のフォルダが見つかりません」「◯本取込(再リンク◯本)」。

## 制約

- バニラ ESM・ビルドなし、サーバーは依存ゼロの Node。
- Chrome / Edge のみ(`showDirectoryPicker` 非対応ブラウザでは今のメッセージを出して何もしない)。
- 後方互換: `videos` の保存形式(`{ id, t, name, durationMs }`)は変えない。
- ファイル版ストア(`policyOn` でない構成)でも追記 API が動くこと。
- 新ロジックには `node:test` の単体テストを付ける(フォルダ名の解釈、フォルダ探索、動画追記のマージ、権限)。テストデータに実名・実位置情報を入れない(フォルダ名の例に人名が含まれるものはテストで使わない)。
- 既存の手動「同期フォルダから取込」は残す(任意のフォルダを選ぶ手段として)。

## builder に任せること

- 月日パーサの正規表現の詳細と、それをどのモジュールに置くか(`src/folderimport.js` への追加を想定)。
- 追記 API のルート配置(`server/routes/compat.js` か新ファイルか)と、ファイル版/DB 版それぞれのストア実装。
- ボタン配置や文言の細部。
- 走査中に別の練習に切り替えたときの扱い(古い結果を捨てる等)。
